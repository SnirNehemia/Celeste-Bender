# Level editor and Story Mode — spec v1 (Stage L0)

A **parallel track**, not an element chapter: it can be built in its own sessions while the element stages (F12, F13, …) go on. Stages are named **L1, L2, …** and listed in `PROMPTS.md` under "Level editor track". The two tracks meet in only two places: the palette catalog (§6) and one small Goal hook for Story Mode (§9).

## 1. What it is
- **Level editor** (main menu → Level Editor): paint rooms, place and set up objects, link switches to doors, lay rooms out on a map into one big level, play-test it at once, save it.
- **Story Mode** (main menu → Story Mode): an ordered list of levels, editor-made levels and the existing chapters alike, played back to back. Finishing one unlocks the next; progress is saved.
- **Dev tool for now.** The editor only works when the game runs from the Godot project. Story Mode plays everywhere, the web build included.

## 2. Decided in Stage L0
| Question | Decision |
|---|---|
| Who saves, where | Dev only: levels are scenes in `res://levels/`, committed to git. One script (`LevelStorage`) knows the folder, so a player-facing `user://` version later is a small change. |
| Controls | Mouse + keyboard in the editor. Play-testing stays keyboard-only. |
| Connecting rooms | A **map of rooms**: rooms of any size placed edge to edge in any direction; gaps in the walls are the exits, the same model `RoomManager` already uses. |
| Palette v1 | Everything that exists: basics, Air, Earth, Fire, enemies (spread over several stages). |
| Paired objects | A **link tool** (L): select an object, click its targets, and lines show the links. |
| Story Mode entries | Any level: editor levels **and** the existing chapters (Air 1–7, Earth 1–10, Fire later). |
| Story progress | Saved, with one-by-one unlock and best time and deaths per level, in `user://`. |
| Existing rooms | Can be **imported as copies** into an editor level. Originals and their build scripts are never touched. |
| New objects from element stages | The element stage that adds an object also adds its palette catalog entry (rule in `CLAUDE.md`). |
| Main menu | Story Mode and Level Editor on top; the chapter and test-room entries move into a "Chapters & test rooms" submenu. |

## 3. Level files
- One level is **one world scene**, `res://levels/<slug>.tscn`, written with `PackedScene.pack()`. It has the same shape as `scenes/earth_world.tscn`: a `RoomManager` root, `Room` children placed edge to edge, `Player`, `RoomCamera`, `DebugOverlay`, plus a small `LevelInfo` node (title, start room, notes).
- **Why a real scene, not a custom data file:** `RoomManager`, the F2 room picker, the screenshot tool, the smoke tests and the Godot editor all work with it unchanged. Links like `Door.switches` are exported node references, and a packed scene already stores those.
- Only nodes owned by the level root are saved. Things that rooms and objects build in `_ready` (GroundPainter, FireGrid, PebbleField, flames, leaves) are rebuilt on load, as they are today.
- `scenes/editor/level_storage.gd` is the only code that lists, saves, loads, renames, duplicates and deletes levels.
- In exported builds the Level Editor entry is greyed out ("dev build only"), detected with `OS.has_feature("editor")`.
- A level edited in the Godot editor still opens in the in-game editor, but the in-game editor rewrites the whole file when it saves.

## 4. The editor screen
- **Layout:** a large canvas; a palette on the left with tabs Basics / Terrain / Air / Earth / Fire / Enemies; a property panel on the right; a top bar with the level title, current room, tool and an unsaved-changes dot; a status line at the bottom with the tile under the mouse and warnings.
- **Resolution:** the game draws at 320×180 with `viewport` stretch, which would make editor text unreadable. While the editor is open it switches the window to `canvas_items` stretch at a larger size (start with 640×360) so text is sharp and the canvas can zoom freely. Play-testing switches back to the game's 320×180 `viewport`. Stage L2 checks that this switch is clean at runtime.
- **Grid:** 8 px tiles. Objects snap to the grid; holding Alt places them freely to the pixel. On the map, holding Alt while moving or placing a room (paste, import) moves it in half-tile (4 px) steps with no snapping; otherwise a room lines up with its side neighbours' tile rows, and a room placed in front of or behind another (another depth) takes the nearest such room's tile rows and columns.
- **Undo/redo for every edit**, using Godot's `UndoRedo` class.
- **Controls.** All of them are InputMap actions named `editor_*`, so the code never reads raw keys:

| Input | Does |
|---|---|
| Left mouse | paint with the current brush / place the current object / select and drag |
| Shift + left drag | fill a rectangle with the current brush |
| Right mouse | erase the tile, or delete the object under the mouse |
| Middle drag, or Space + left drag | pan |
| Mouse wheel | zoom (whole steps, so pixels stay square) |
| Ctrl+Z / Ctrl+Y | undo / redo |
| Ctrl+S | save |
| Ctrl+D / Delete | duplicate / delete the selection |
| Page Down / Page Up | show the depth behind / toward the front, in the map and the room view (§5a); also the depth slider in the status line |
| L | link mode for the selected object (§7) |
| E | the eraser on / off: click or drag removes objects (zones too), else tiles on every terrain layer; Shift+drag clears a block (tiles on every layer, objects fully inside) |
| H, or the "?" button | the quick reference: every key, read from the InputMap |
| M | toggle the map view (§5) |
| S / I (map view) | make the selected room the start room / import a room as a copy |
| Tab / Shift+Tab | play-test from the start / from the mouse (§8) |
| G | toggle the grid |
| [ / ] | smaller / bigger free-hand brush for terrain and the eraser's tiles (1×1 to 8×8; the hover outline shows it) |
| B / F | the Brush tool (paint with the last terrain) / the Fill tool |
| Shift + Fill click | fill (or clear) every cell of the room holding the same tiles, connected or not: replace a terrain room-wide |
| P | eyedropper: the object under the mouse, else the tile's terrain, becomes the tool |
| Ctrl+F | search the palette (every word must match a name, tab or element; Enter takes the first) |
| 1 – 9 | the quick bar: the 9 things used last, in fixed slots (bottom of the palette) |
| Select + Shift drag | mark a region (may cross rooms); Ctrl+C / Ctrl+X copy / cut it, Ctrl+V pastes at the mouse, Ctrl+Shift+V pastes mirrored |
| J (hold) | jump reach from the tile under the mouse (§4a) |
| T / Ctrl+T | show / hide the last play-test's trail and this level's deaths / clear the deaths |
| Esc | leave link mode, or go back to the level library (asks first if there are unsaved changes) |

- **Painting across rooms.** A free-hand stroke, a Shift-drag rectangle, the eraser's drag and its Shift-drag block carry on into the rooms next door: each tile goes to the room it lies in, and the whole thing is one undo step. Rooms stay separate in the game (camera, reset, water and fire per room); only the editing crosses. The Fill tool stays in its room. A room's top-row tile looks into the room above for its top edge, so ground running across a border has no seam line.
- **Zones** (wind, no-glide; catalog `is_area`) are picked only by their outline's edge, so clicks inside reach what's in them. With the zone's own tool, the eraser or a right-click, anywhere inside works.
- **Level library** (the first screen of Level Editor): the list of levels in `res://levels/`, with New, Open, Duplicate, Rename and Delete (Delete asks to confirm).

### 4a. Designer tools (after L15)
- **Brush tool** (B), next to Fill: back to painting with the terrain chosen last; its button is pressed whenever a terrain paints.
- **Eyedropper** (P): objects first (zones from inside too), else the top terrain layer at the tile; on a shared layer (Overgrown looks, ice slopes) the entry whose tile matches.
- **Palette search** (Ctrl+F, `PaletteSearch`) and the **quick bar** (1–9, `QuickBar`): slots don't move; a new thing takes a free slot, else the one used longest ago. Tools get no slot.
- **Shift+Fill**: the Fill tool's area becomes every cell of the room with the same layers, not only the connected ones (this is "replace terrain in a room"; plain Fill only reaches connected cells).
- **Copy / paste** (`EditorClipboard`): Select + Shift+drag marks a region (dashed cyan; Esc drops it). Ctrl+C copies its tiles (every terrain layer) and every object wholly inside (not the spawn point); Ctrl+X also erases it like the eraser's block. Ctrl+V pastes with the region's top-left on the mouse's tile; with the Select tool on, a ghost shows where. Pasting lays tiles on top (empty cells don't erase), crosses rooms like strokes, and is one undo step; the pasted area becomes the region. Links between copied objects follow the copies; links to things outside are dropped. Ctrl+Shift+V mirrors left-right: ice slope tiles, spikes facing left/right, arrows and point properties (wind, rails, vine ends), rotation, a sentry's wall side.
- **Play-test record** (`PlaytestRecord`): the last play-test's path (broken at respawns) and red X's where you died, over all play-tests of the level (kept in `user://editor_playtest_record.cfg`). T shows / hides, Ctrl+T clears the deaths.
- **Play-test cheats** (`PlaytestCheats`, only in a play-test from the editor): I invincible (a pit and R still kill), N fly through walls with the arrows (can't die), O 1× → ½× → ¼× speed, P pause, . one physics frame while paused. A yellow line at the top lists what's on; leaving the play-test switches everything off.
- **Jump reach** (hold J, `JumpReach`): from the tile under the mouse (standing on it if solid, else on the tile below), the full jump's arc both ways with a running start (white) and the same with a glide from the top (light blue), traced from PlayerTuning frame by frame, with "jump N up, M across" in tiles. Not included: gust, wind, water, ice, wall jumps. The arc is the middle of the feet; the hitbox reaches half its width further.

## 5. Rooms and the map (M)
- The **map view** shows the whole level zoomed out: each room is a rectangle with its name and a tiny drawing of its tiles.
- Drag on empty space to make a room, drag a room to move it, drag its edges to resize it. Rooms snap to the grid and to neighbouring room edges. The minimum size is one screen (320×180); L7 matches the way the existing rooms handle 180 px being 22.5 tiles.
- Overlapping rooms are refused (drawn red). On shared edges the map marks the openings, the exits, in green.
- One room is the **start room** (a star). The Player starts at its SpawnPoint.
- Double-click a room to edit it. In the room view the neighbouring rooms are drawn dimmed so you can see what's next door. A brush stroke only paints the room under the mouse, because tiles belong to rooms.
- **Room settings** (shown in the property panel when nothing is selected): title, size, elements allowed (Air / Earth / Fire), fire start pips, and the one-key Earth experiment. These are the Room's own exported settings.
- **Backdrop** (added after Stage W7b, `GAME_DESIGN.md` §2): two Room settings in the same panel, `backdrop_theme` (Mountain / Temple / Forest / Desert / Underwater / Jungle / Shore / Volcano / Sanctum / Deepwood / Cavern / None) and `backdrop_altitude` (Underground / Surface / Skyline). Both default to Auto: the look from the room's contents, the altitude from its height against the start room (below it: underground, above it: skyline). The map shows each room's result under its name ("Forest, skyline (auto)") and a strip along its bottom edge tinted by altitude (orange underground, green surface, blue skyline). Moving the start room re-decides every Auto altitude. Setting several rooms at once (after the backdrop play-test): on the map, drag a box over empty space to select every room it touches, Ctrl+click to add or remove one; a room setting changed in the panel then goes to all of them (one undo step), and the right-click menu has "Backdrop look of N rooms..." and "Backdrop altitude of N rooms...". New rooms now come from the right-click menu on empty space ("New room here", one screen; or "Draw a new room", then drag its size), since a plain drag selects. K (`editor_backdrop_preview`, also in the right-click menu and the room panel) opens the **backdrop preview**: every look on its own, Left/Right for the look, Up/Down for the altitude (with the same changes as in play: soft between surface and skyline, a break through rock out of the ground), Space to stop the camera drift, Enter to use the shown look and altitude for the selected rooms. (The step-1 **Back room** field, `back_room`, is gone: Stage D1 replaced it with depths, §5a.)
- **Import room as a copy:** pick any Room from the existing worlds (Air 1–7, Earth 1–10, the Earth, Fire and mixed test rooms, other editor levels) and click where it goes. The copy becomes part of this level and isn't linked to the original afterwards.
- As built (L7): `map_view.gd` (MapView) holds the map's tools and snapping. Widths are whole tiles (at least 320), heights 180 + whole tiles, so the last tile row always hangs half below the room. Positions snap to the 8 px grid or to a neighbour's edge (a room under a 180 px room starts at y = 180). A new room is empty but for its spawn point; the room panel's "Fill edges" button walls it in with the terrain chosen last. Dragging a left or top edge keeps the contents in place in the level (they move inside the room by whole tiles); tiles outside a shrunk room are cut off (undo restores them). Openings are found by sampling both sides of each shared edge every 4 px for solid tiles. Map keys: S start room, Delete delete room (not the start or the last room; links into it are dropped in the same undo step), I import, Esc closes. The camera has two extra zoom-out steps (1/4, 1/8) for the map. `room_import.gd` (RoomImport) lists the sources (MainMenu.CHAPTERS, the Air test rooms, other levels) and copies a room: one that is its own scene file is rebuilt from that file as a root, so the saved level holds no hidden tie to it; links to things outside the room are dropped. `room_import_picker.gd` is the list (a Tree, a world's rooms read when its folder opens).

### 5a. Depth layers and depth gates (built, Stages D1-D4)
Decided with the developer after back rooms step 1 (`GAME_DESIGN.md` §2); the full working plan is `DEPTH_LAYERS_PLAN.md`:
- **Any number of DEPTHS.** Every room has a `depth` (0 = front, 1 = behind it, 2 = behind that...). From depth N the player sees depth N+1 behind the room they're in, hazed, never the outer depth N-1: going deeper into a cave leaves the outer cave behind.
- **Where rooms are.** On the map, a room has a MAP position like now; rooms of different depths may overlap there (that's what "behind" means), rooms of the same depth may not. In the game world each depth lives in its own band far away (`world = map + depth * DEPTH_SPACING`, a big vertical offset), so different depths never touch: no physics between them, the room-to-room code works as now, and the back view is just a second camera looking at the next band. Anything that measures heights (AUTO backdrop altitude) uses map positions. This replaces step 1's `back_room` text field: what's behind a room is whatever the map has behind it.
- **The view behind** (BackRoomView, reworked): the next depth's band through a SubViewport, opaque and hazed (`back_room_haze.gdshader`, already built), sliding slower than the front (parallax) but **pinned at gates**: the back layer lines up exactly with the front at the gate nearest the player, so a gate's twin is right behind it when you stand in it; away from the pin it slides at PARALLAX. When the nearest gate changes, the pin glides there instead of jumping. A room with no gate pins at its middle.
- **Depth gates.** A placeable pair: a gate at depth N and its twin at the same map spot at depth N+1 (the editor finds and makes twins, see below). Stand in one and press **Up** (`move_up`, no new key) to step through: the front fades and the layer behind clears and comes forward (about half a second), then you're in the twin at the other depth, and what's behind is now one depth deeper. The twin takes you back. Dying respawns you in the room you're in, at its depth.
- **Map view (M), depth toggle.** `editor_depth_deeper` / `editor_depth_shallower` (Page Down / Page Up) step the depth being edited, shown as "Depth 1 of 3". That depth is drawn as now; the next deeper one is drawn UNDER it, hazed like in the game, with its outlines in a depth color, so you see which room is behind which. Gate pairs are marked and joined. Hovering a room outlines the rooms behind it. New rooms are made at the shown depth; overlap is only refused within one depth.
- **Room view.** Editing a room at depth N shows depth N+1 hazed behind it, lined up 1:1 (not parallax), so gates and twins can be placed by eye.
- **Placing gates.** Placing a gate where a room exists one depth behind puts its twin there in the same undo step; where there's none, the gate shows "no twin" (red) until a room is made behind it, and the map offers "Add twin". Moving or deleting a gate does the same to its twin.
- **Decided while building (D1-D4):**
  - **A room's depth is where it is,** not a stored number: `Room.get_depth()` is the band its middle is in (`Room.DEPTH_SPACING` = 20 000 px). Moving a room to another depth moves it by whole bands, so its depth and its place can never disagree. Helpers: `Room.depth_offset(depth)`, `Room.depth_at(y)`, `Room.to_map_point(point)`, `get_map_position()`, `get_map_bounds()`.
  - **The editor works in world space and shows one band at a time.** The camera looks at the shown depth's band, so snapping, overlaps, openings, new rooms, imports and pastes only ever meet rooms of that depth (the other bands are far away) and needed no changes. `LevelEditor.get_shown_depth()` is the map's `shown_depth` or, in the room view, the band the camera is in.
  - **The depth behind in the editor** is `EditorBackView`: a SubViewport sharing the editor's World2D, its camera a copy of the editor camera one band down, drawn through the game's haze shader over the room background and under the level. The editor's own backdrop and overlay are on render layer 2 only (`visibility_layer`), so the SubViewport (`canvas_cull_mask` = layer 1) doesn't draw them. On the map, the depth IN FRONT of the shown one is drawn as faint outlines only, to find your way (in play it's never seen). Each room behind gets a dashed teal outline and "behind: <name>"; the room under the mouse brightens the ones behind it.
  - **Moving rooms between depths** is a right-click row on the map ("Move N rooms behind" / "to the front"), refused if they'd overlap a room there. "Add missing gate twins in N rooms" is the "Add twin" row.
  - **Twins are found, never stored** (`DepthGate.find_twin`): the gate within 4 px of the same map spot, one depth either way, in the same level. A gate with twins on both sides leads behind. Up works in any state but dead; a gate without a twin is dimmed in play and does nothing.
  - **The step** (`RoomManager.go_through_gate` checks the gate, `GateStep` plays it, `GateStep.STEP_TIME` 0.3 s): the player freezes; the rooms of the current depth fade out while the layer behind loses its haze (going in), or fades away with them (going out); the player moves by exactly the band difference, so they stand in the twin where they stood in the gate; the camera starts where the view behind was looking and glides 0.2 s to where it settles in the new room; going out, the front rooms fade back in. The backdrop changes look at once across a depth change (no scroll: the step hides it), and measures its parallax on the map, so a gate never scrolls it by a band.
  - **Pinned parallax:** `view = depth_offset(1) + PARALLAX * camera + (1 - PARALLAX) * anchor`, with `anchor` where the camera settles when the player stands at the pin (`RoomCamera.get_center_for`, so clamping at room edges is included). The pin is the nearest gate with a twin behind; within it (and a tile around it, `PIN_REACH`) the anchor follows the player, so anywhere inside lines up exactly (the smoke test measures 0 px). A new pin glides over `PIN_GLIDE_TIME` 0.3 s. PARALLAX went from 0.6 to 0.75: the layer behind is a real room only a little further away.
- **After the first D play-test (1 Nov 2026):**
  - **Stepping out is the step in, reversed:** the swap comes first; the room you leave shows behind, clear and full size, exactly where you were looking, and hazes and shrinks back while the rooms in front fade in over it (`GateStep._step_out`, `BackRoomView.begin_return`, `RoomCamera.hold_at`). It used to fade everything out and back in.
  - **An arrow inside each gate** says where it leads: up = deeper, down = back out, the same crisp pixel arrow as the one bobbing above the gate (`DepthGate._draw_arrow`), bobbing the way it points. The arrow above (while you stand in it) is always up: Up is the key either way.
  - **Even deeper layers, as a test** (`BackRoomView.DEEPER_LAYERS` = 2): behind the depth behind, depths N+2 and N+3 show too, each fainter by haze only (0.7 / 0.85; opaque, so the backdrop never shows through them), slower and smaller, pinned at the same spot. A gate's step moves every layer one step forward (each eases into the next nearer one's haze, size and speed, then hands its picture over), so nothing vanishes and comes back; stepping out runs it backwards. The editor shows them the same way under the depth behind. This bends the "only N+1" decision above; set the constant to 0 to go back.
  - **Fainter means "into the background":** every layer behind is hazed toward the backdrop's MAIN COLOR (`Backdrop.get_main_color`: the look's painted layers laid over each other far to near, averaged over the screen, worked out once per look and altitude), not a fixed cool gray. So rooms further back sink into the setting: darker in caves and at night, lighter in bright skylines. The color eases over when the look changes; the editor's previews use the current room's look.
  - **Fixed:** with nothing behind the room you're in (the deepest depth), the last picture of the view behind stayed on screen, which was the very room you stand in. A SubViewport that stops rendering keeps its last frame, so the pictures are now hidden then.
  - **Flatter and softer behind** (picked by play-test from three looks: haze only; this; this plus a shadow the front casts onto the layers behind): every layer behind also has its contrast and saturation squashed (×0.65 and ×0.6 per depth back) and a soft blur (0.8 px per depth back), so nothing behind is as crisp or as colorful as what you can stand on. `back_room_haze.gdshader`, set per layer by `BackRoomView.apply_look` from how far back it looks, so gate steps blend it; the editor's previews look the same.
  - **The backdrop zooms with depth** (`Backdrop.ZOOM_PER_DEPTH` 0.08 per depth, at most 1.24, from the screen's middle): the deeper you are, the closer the painted background. A gate's step zooms it along (`Backdrop.zoom_to`, over the step and the settle), so stepping in pushes into the scene and stepping out eases back.
  - **The layer behind is drawn a little smaller** (`BackRoomView.BACK_SCALE` 0.92, smoothly filtered, so a touch soft) around the pin gate's middle, as something further off would be; the twin stays centered behind its gate. Stepping in grows it to full size as the haze lifts; stepping out shrinks it back.
  - **Depths in the room view too:** Page Down / Page Up work there (`LevelEditor.show_depth`: the camera hops a band, the room there becomes current), and a **depth slider** sits at the right of the status line (0 to one past the deepest).
  - **The depth in front, very faint** (`EditorDepthView` with direction -1, alpha 0.16), drawn over the level while editing a deeper depth, in the room view and the map. `EditorBackView` became `EditorDepthView`, one class for both.
  - **Room edge rims** (`scenes/rooms/room_edge_rim.gd`, every room makes one): the painter treats everything past a room's edge as ground, so edge walls ended in straight cuts, which showed when the room was seen from another depth. The rim draws a thin crust (edge line, crust, light top rim, a 1 px wobble) just outside edge tiles wherever no room of the same depth carries on. Display only.
  - **One exception to "no per-object code in the editor"** (§6): the twin steps for depth gates live in `gate_twins.gd` (`GateTwins`: static helpers that `level_editor.gd` calls on place / move / delete, and the map's "Add missing gate twins"), since a twin is a second object in another room, which no catalog field describes.
  - Not built: a read-only "Depth N" row in the room panel (the map's label and messages say it), and a per-depth haze (only the next depth is ever shown, so one value is enough).

## 6. The palette catalog
- `scenes/editor/palette_catalog.gd` has one entry per placeable thing, grouped by family. Entry fields:
  - `id`, `display_name`, `family` (basics / terrain / air / earth / fire / enemies), `kind` (object or terrain brush)
  - `scene` for an object; layer name + tileset + layer script for a terrain brush
  - `editor_color` for the palette swatch and the stand-in drawing, if the object doesn't draw itself in the editor
  - `editable_properties`: the export names shown in the property panel (design settings only, never tuning numbers like gravity or friction)
  - `size_property` (drag handles, e.g. `door_size`, `zone_size`, `tile_count`) and `point_properties` (drag handles for points, e.g. the vine's `end_point`, the sail's `rail_start`/`rail_end`, the leaf's `travel`)
  - `link_property` + accepted target type (e.g. Door `switches` ← Switch, HangingPlatform `vines` ← Vine, Crate `hung_from` ← Vine, EnemyGate `enemies` ← enemy). A crate's `hung_from` takes **vines only**: linked to a plate or windmill, it would float, waiting for a vine to snap.
  - `placement` (grid / standing on the floor / free) and `one_per_room` (SpawnPoint)
  - As built (L3-L4): `kind` (TERRAIN / SPAWN_POINT / OBJECT / STRIP). `bounds` is how the outline is found relative to the object's own origin (SIZE_TOP_LEFT, SIZE_BOTTOM_CENTER, WIDTH_CENTERED, FIXED `local_rect`, plus the spawn marker and spike strip), because objects put their origin in different places (door: top-left, crate: feet, crystal: center). `placement` (TOP_LEFT / ON_FLOOR / HANGING / CENTERED) says where a new object's outline lands on the clicked tile: an outline an even number of tiles wide is centered on the tile line nearest the mouse, so its edges stay on the grid. Alt places freely. `start_positions` lists positions an object works out once in `_ready` (a leaf's home, a sail's rail ends), which the editor updates after a move. `editor_color` + `arrow_property` give a stand-in to objects that draw nothing while editing (the wind zone: only particles).
- Terrain brushes: Ground (`Tiles`), Earth, Hidden chamber, Grass, Thicket (burns slowly), Grass / Thicket cover (burn at once; the Overgrown layer), Cracked wall, Stone wall, Water. **One terrain per cell** (after Stage W2): painting a terrain erases every other terrain layer in that cell (catalog `carves_layers`, set by `PaletteCatalog._assign_carving`); Water erases nothing, and a hidden chamber keeps the water in it. Each paints its TileMapLayer, and the first stroke creates the layer in that room.
- **Cross-track rule** (also in `CLAUDE.md`): from Stage L4 on, any stage that adds a placeable object or terrain layer adds its catalog entry and keeps the editor smoke test passing. The editor holds no per-object code. If an object needs special editor behaviour, that becomes a new catalog field, not an `if` in the editor.
- **Families in v1:**
  - Basics: spawn point (moved, never deleted: Room needs `$SpawnPoint`), goal (stands on the clicked tile), spikes (dragged along a row or column; facing from the ground beside them, R turns)
  - Depth gate (Objects tab, Stage D2, §5a): stands on the clicked tile; placing, moving and deleting it acts on its twin too
  - Air: wind zone, wind crystal, gust diamond, crate, windmill, leaf platform, sail platform, door, pressure plate, no-glide zone
  - Earth: earth ground (brush), cracked wall, stone wall, boulder, loose rocks. After Stage W2 the walls are terrain brushes (Breakable tab): each connected patch of a `CrackedWalls` / `StoneWalls` layer (`WallLayer`, `scenes/objects/wall_layer.gd`) becomes one CrackedWall / StoneWall node (`wall_cells`, shape code in `wall_shape.gd`), built in `_ready` and never saved; old wall objects in a level turn into tiles when it's opened (`RoomLook.prepare_for_editing`). The L8 notes below about wall sizes are history. As built (L8): the Earth brush is in the Terrain tab (`layer_script` EarthLayer, one tile: `tile_plain` = `tile_top_edge`; `room_settings_on_create` turns `earth_allowed` on). Walls are sized in tiles (`size_unit` = 8, a Vector2i, also in the property panel). Boulder and loose rock are `RockSpot`s (`scenes/objects/earth/rock_spot.gd`), which lay a loose Boulder in play and again after each reset. `room_look.gd` rebuilds an Earth room's GroundPainter after every tile change, so it looks as in play. After the L7/L8 play-test: rooms the editor makes have `Room.painted_ground` on (the painter draws plain ground as stone too), and every entry has a `hint`, shown as the palette button's tooltip, in the status line and in the property panel. During a play-test the editor's own copy of the level leaves the scene tree, so group lookups find only the play copy.

## 7. Properties and links
- **Property panel:** a widget for each type. bool → checkbox; int/float → number field (arrows or drag); enum → dropdown; Vector2 → two fields; direction vectors such as `wind_direction` → an 8-way picker. Every change can be undone and shows at once, because the objects' setters already redraw (e.g. `door_size`).
- As built (L5): the panel reads each setting's type and hint from `get_property_list()`, the same info Godot's Inspector uses, so a new object needs no panel code, only its `editable_properties`. Quick changes to one setting (scrubbing a number) merge into one undo step (`UndoRedo.MERGE_ENDS`). Handles are in `editor_handles.gd`: size corner, width edge, strip end, and one per point property. With nothing selected, the panel shows the settings of the room last clicked in. On opening, the camera zooms to the largest step at which the start room fits between the panels.
- **Links (L):** with a linkable object selected, L starts link mode. Click targets to add or remove them, and Esc or L ends it. Links are always drawn as dim lines, bright for the selected object. Links may cross rooms. Deleting a target removes it from every link list, in the same undo step as the delete.
- As built (L6): what fits is checked by script class, walking the `extends` chain, so a PressurePlate counts as a Switch. Each link or unlink click is its own undo step, never merged. The panel's last line shows the link count. Esc leaves link mode before it leaves the editor, and Tab ends link mode before playing.

## 8. Play-test
- **Tab** plays from the start room. **Shift+Tab** drops the player at the mouse in that room; the room's SpawnPoint is still the checkpoint.
- Nothing has to be saved first: the editor packs the level in memory and runs that copy. **Tab** goes back to the editor with the view, selection and undo history as they were. The pause menu gets a "Back to editor" entry.
- Checks before playing: the start room (or, for Shift+Tab, the room under the mouse) needs a SpawnPoint, and this one blocks. A missing Goal, rooms without a SpawnPoint, unreachable rooms and broken links are only warnings, shown in the status line when you come back.
- The play copy runs without its EndScreen, which would reload the current scene, and that's the editor.
- Reaching the Goal in a play-test shows "Goal reached — time, deaths" and goes back to the editor.

## 9. Story Mode
- `res://levels/story.tres` is a `StoryList` resource with ordered entries {display title, scene path}. An entry can be an editor level or an existing chapter world (`scenes/world.tscn`, `scenes/earth_world.tscn`, later the Fire world).
- **Story screen:** Continue · Level select (finished levels get a ✓ with best time and deaths, the next one is open, the rest are locked) · New run (resets progress, asks to confirm).
- **Edit order** (dev builds only, on the same screen): Shift+Up/Down moves an entry; Add picks from levels and chapters; Remove; Rename changes the display title. Changes save at once.
- **Playing:** each level runs as chapters do now (GameState timer and deaths). At its Goal comes a level-complete card (title, time, deaths), then the next level. After the last one comes the end screen with the run's totals.
- **Progress** lives in `user://story_progress.cfg` (a `ConfigFile`): finished entries and best time and deaths, keyed by **scene path**, so reordering doesn't lose progress. An entry is open if it is first or the entry before it is finished.
- **Goal hook:** today Goal → `GameState.finish_run()` → `run_finished` → EndScreen. Story Mode has to decide what happens at the goal. That is one small hook in GameState and EndScreen (e.g. a "story run" flag the end screen respects), the only gameplay code this track touches.
- As built (L11): `GameState.is_story_run`; in a story run the EndScreen only freezes the player. `StoryPlayer` (`scenes/ui/story_player.gd`) is one node under the tree root, so it outlives each level's scene change: it opens each level, saves progress at the goal, shows the level-complete card, and after the last level an end card with the totals of that sitting, then returns to the Story screen. The main menu and the Story screen end a story run (`StoryPlayer.stop()`). `story.tres` lives at `LevelStorage.story_path()`. Progress: `StoryProgress` (`scenes/ui/story_progress.gd`); a finished entry stays open wherever it's moved. Shift+Up/Down = InputMap `story_move_up` / `story_move_down`.
